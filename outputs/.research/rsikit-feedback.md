# RSIKit mechanism donors: reflection, memory, and selected optimizers

Research note, 2026-09-16. Scope: fifteen local implementations selected for mechanisms relevant to evolutionary/code agents. These are conceptual module proposals, not implementation changes or a survey of all 86 prompt optimizers. Read each `agent.py`, relevant README sections, reflection/memory/operator prompts, and `tauchi_gpt/memory.py`; independently checked the primary sources linked below. No live optimization, training, or benchmark reproduction was performed.

The strongest separation is **what gets updated, what evidence justifies that update, and how long the update survives**. “Reflection” alone is not a useful module boundary: it can rewrite one answer, change retry context, extract transferable rules, rewrite reusable instructions, or prepare weight-training data.

## Per-agent matrix

All implementation claims in this matrix refer to the local source. H means high confidence in the inspected local control flow; it does not mean demonstrated performance. Source confidence concerns attribution of mechanisms, not benchmark efficacy.

|---|---|---|---|---|
| **Self-Refine** | Current text plus every `(output, feedback)` pair; revises the same artifact within one input. State resets each run. | Same model supplies its own critique. Exact `NO_FEEDBACK` or a caller stop callback ends iteration. Returns the latest artifact, not a measured best. The final artifact receives feedback even at the revision cap. | Separate `critique(current)` from `revise(full_history)`. Full history is revision context, not transferable memory. | H: [loop](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/self_refine/agent.py#L80), [history prompt](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/self_refine/prompts/refine.j2#L1). The [paper](https://arxiv.org/abs/2303.17651) independently confirms same-model generation, critique, refinement without training. No external acceptance signal. |
| **CRITIC** | Current artifact, critique, and actual tool results; correction within one input. Fresh verification Session each round. | Model chooses external tool calls; a structured model judgment decides correctness. Acceptance requires at least one successful nonblank tool result. This guards evidence presence, not relevance or correct interpretation. | Tool-interactive verification with preserved evidence passed separately into revision. | H: [verification](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/critic/agent.py#L127), [correction loop](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/critic/agent.py#L90), [paper](https://arxiv.org/abs/2305.11738). At the budget cap the final correction is returned **without re-verification**; `budget` and `unchanged` are not verified success. |
| **Reflexion** | Evaluated episode records and bounded deque of verbal reflections; guidance persists across attempts at the same task, resets on `run`. | Caller evaluator returns independent `passed`, optional scalar reward, and feedback. Only `passed` stops; reward does not rank trials. Reflects only on failure when another attempt remains. | Distill `trajectory + evaluation + prior_memory` into an actionable next-attempt plan; rerun an actor from a fresh episode using only the bounded reflections. | H: [loop and actor boundary](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/reflexion/agent.py#L102), [reflection prompt](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/reflexion/prompts/reflect.j2#L1), [paper](https://arxiv.org/abs/2303.11366). Returns last evaluated trajectory, not best reward; does not itself learn cross-task memory. |
| **ExpeL** | Persistent in-memory pool of completed experiences across training tasks, weighted insight rules, cached task embeddings. Gather appends; extraction rebuilds rules from seeds and the current pool. | Environment callback supplies observations and success; actor cannot declare success. Same-task success/failure pairs and groups of successful tasks feed rule extraction. Held-out evaluation is one attempt, with no reflection or training-pool update. | Three independently useful modules: contrastive rule extraction; validated `ADD/EDIT/UPVOTE/DOWNVOTE` rule maintenance; retrieval of successful demonstrations by task similarity. | H: [gather/extract](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/expel/agent.py#L219), [rule updates](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/expel/agent.py#L67), [retrieval/evaluation](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/expel/agent.py#L264), [paper](https://arxiv.org/abs/2308.10144). Failed-only tasks contribute no extraction evidence; retrieval ranks task descriptions by inner product, not failure similarity. Disk persistence remains caller-owned. |
| **TAUCHI-GPT** | Pending task queue, completed artifacts, evaluations, source-document chunks, generated-result chunks, optional per-task critique/revision history. All reset at `run`. | Self-critique can revise each task artifact. Caller evaluator determines whole-goal completion and supplies replanning feedback. Retrieved passages are contextual evidence, not correctness labels. | Retrieval-informed execution followed by result storage, new-task generation, and reprioritization; preserve document/result provenance and exact quote references. | H locally: [execution and replanning](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/tauchi_gpt/agent.py#L180), [quote checks](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/tauchi_gpt/agent.py#L78), [memory](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/tauchi_gpt/memory.py#L1). It is working memory and replanning, not demonstrated persistent learning. |
| **Meta-Prompting Protocol** | Reusable instruction plus curated demonstrations; proposed/accepted instruction history, train/gold evaluations, clustered failure reports. Update across a batch of tasks. | Generator produces artifacts; a separate auditor or evaluator sees artifact, case, hard rules, and reference, but not the candidate instruction. Optimizer sees training failures only. Rejects any per-case gold regression or lower training mean; optional review callback. | Blind audit; exact-partition aggregation of failure critiques; successful-example promotion; regression-gated instruction+example replacement. | H locally: [audit and aggregation](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/meta_prompting/agent.py#L129), [proposal and acceptance](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/meta_prompting/agent.py#L248). [Paper](https://arxiv.org/abs/2512.15053) is a theoretical protocol; local strict regression gate, clustering contract, caps, and stopping details are explicit implementation choices. This is **not** the separate `meta_prompting_scaffolding` method. |
| **Promptbreeder** | Coupled genome: prompt sequence, mutation instruction, verified working examples, elite lineage; population and best-ever measurement. Domain-level prompt/operator evolution. | Caller evaluates the whole sequence and returns score plus correct workings. Binary tournament preserves winner and replaces loser with the winner's mutated child **even when that child scores worse**. Fitness drives selection but numeric fitness is not put into mutation prompts. | Evolve the variation instruction itself (`hyper_zero`, `hyper_first`); infer instructions from successful workings (`lamarckian`); derive proposals from diverse populations or elite lineages; separately vary examples. | H: [genome](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/promptbreeder/agent.py#L20), [operators](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/promptbreeder/agent.py#L224), [tournament](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/promptbreeder/agent.py#L279), [paper](https://arxiv.org/abs/2309.16797). Local seeds draw from a co-author's later minimal implementation, not a verified release of the original experiments. Meta-operator fitness is indirect through offspring, not an independent bandit learner. |
| **EvoPROMPT** | Prompt population with scalar fitness; GA or DE generations. Reusable task instructions change across evaluation batches. | Caller evaluator provides nonnegative scalar fitness. GA samples parents proportionally and keeps top N from parents+offspring. DE compares each trial to its target and replaces only on strict improvement. | Textual differential evolution: identify donor differences → mutate those differences → apply to best prompt → cross with target. GA crossover+mutation is the simpler alternative. | H: [variation pipeline](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/evoprompt/agent.py#L89), [selection](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/evoprompt/agent.py#L127), [paper](https://arxiv.org/abs/2309.08532). | **GEPA** | Candidate dictionaries of named prompts, aligned per-validation-instance score vectors, ancestry, per-candidate module cursor. Edits one reusable prompt module at a time. | Caller returns score, output, trace, global feedback, optional module feedback. Mutation sees training rollout evidence; parent and child are measured on the same minibatch; only strict mean improvement earns full validation/admission. | Trace-conditioned component mutation; instance-winner coverage selection preserving specialists; ancestry-aware merging of complementary module changes; staged evaluation. | H: [mutation](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/gepa/agent.py#L116), [coverage weights](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/gepa/agent.py#L48), [merge](https://github.com/StuartFarmer/slick-bits/blob/355335f290ddb1ea9b08dbd41aeccc6136779a69/gepa/agent.py#L167), [paper](https://arxiv.org/abs/2507.19457). | **OPRO** | Archive of unique text candidates, measured scores, iteration numbers; strongest bounded history presented from worst to best. Across search steps. | Caller supplies scalar objective. ## Conceptual modules to extract

These are responsibilities and data contracts. They do not each require a class, package, registry, or framework. Integrate them into the existing RSIKit abstractions after comparing its current implementation.

| Module | Inputs → outputs | Donors and separable variants | Important boundary |
|---|---|---|---|
| **Observation and evaluation** | Artifact or episode, instance, execution context → success, objective measurements, diagnostics, trace/evidence, cost | Reflexion `Evaluation`; CRITIC evidence; GEPA global/module feedback; human vote events | Keep measured outcome separate from model opinion. Preserve origin, instance/split, candidate identity, and evaluator identity/version. A scalar alone loses the information reflection needs. |
| **Feedback interpretation** | Current artifact/trace + evidence + requirements → critique or failure groups | Self-Refine intrinsic critique; CRITIC tool-grounded critique; Reflexion next-attempt plan; Meta-Prompting clustered cross-case failures | Different outputs: artifact-specific defect, retry plan, and cross-task rule should not share an untyped “memory” string. Clustering is useful only once there are many reports. |
| **Context and memory** | Query + stored records + scope/budget → selected context | Raw revision history (Self-Refine); bounded reflection deque (Reflexion); success demonstrations and weighted insights (ExpeL); source/result passages (TAUCHI); score history (OPRO); verified workings (Promptbreeder) | Separate storage from retrieval and extraction. Specify lifetime: within revision, task retries, optimization run, or across tasks. Record whether contents are observed, generated, or verified. A vector database alone is not learning. |
| **Knowledge extraction and maintenance** | Success/failure episodes or successful examples + current rules → proposed rule edits/instruction/demo updates | ExpeL contrastive extraction and weighted rule edits; Promptbreeder Lamarckian operator; Meta-Prompting demo promotion; STaR data harvesting | Learn from actual evidence, retain evidence links and learning split. A correct final answer does not prove every intermediate step. ExpeL's rule importance is accumulated votes, not calibrated confidence. |
| **Variation operators** | Parent artifact(s), selected component, operator instructions, evidence/context → candidate change and lineage | Feedback revision; GA crossover/mutation; EvoPROMPT donor-difference editing; GEPA targeted module revision; Promptbreeder lineage/EDA/hypermutation | Reuse the candidate representation already present in RSIKit. Distinguish the object being improved from the instruction that improves it. Start with a few functions; add operator learning only when the experiment calls for it. |
| **Search and survival** | Candidate measurements and existing archive/population → parents, survivors, incumbent, archive changes | Strict hill-climb; global GA elitism; DE target replacement; Promptbreeder loser replacement; GEPA instance coverage; human steady-state replacement | Parent selection, child admission, and best-result return are three decisions. Do not collapse them into “keep better”: several algorithms intentionally retain worse/unrated children while preserving a separate best archive. |
| **Evaluation allocation and regression gates** | Candidate batch, prior observations, remaining budget, split plan → next measurements and accept/reject | GEPA cheap paired screening then full validation; EPO fixed-budget elimination; human vote coverage; Meta-Prompting per-case regression rejection | Fixed-arm allocation differs from growing-population search. Paired cases improve comparability but do not remove stochastic evaluation error. Training/validation search must leave a separate final test set. Cache only when evaluation semantics allow it. |
| **Task and attempt control** | Goal/task, pending work, progress, budget, feedback → retry / revise / new task / stop | Reflexion retry; Self-Refine stopping; CRITIC verify/revise; TAUCHI task creation/reprioritization | Preserve distinct terminal states: success, verified, stagnation, exhausted tasks, exhausted budget. A final changed artifact may need evaluation before release even if the donor algorithm returns it unverified. |
| **Learning backend** | Verified training examples + base checkpoint + training policy → new model/provider | STaR | Separate optional integration. Weight updates have different persistence, cost, and rollback semantics from editing instructions or memory. Do not simulate STaR by returning an unchanged provider. |

The modules share a small conceptual record set: **candidate**, **evaluation observation**, **experience**, **knowledge item**, and **change decision**. Each needs stable identity and provenance where it crosses persistence or comparison boundaries. This is a design inference from the code, not a claim that every donor exposes these exact records or that RSIKit lacks them.

## Differences that must survive composition

1. **Critique is not evaluation.** Self-Refine uses intrinsic opinion; CRITIC adds tool evidence but a model still interprets it; Reflexion and GEPA accept caller measurements; ExpeL uses environment success. RSIKit should allow all of these without reporting them as equally strong verification.
2. **Retry memory is not transferable knowledge.** Reflexion resets its deque each task/run. ExpeL explicitly has a gather/extract/evaluate split and learns across tasks. TAUCHI stores sources and generated results during one run. Copying all three into the same persistent store changes their learning semantics.
3. **Accepted is not best and latest is not verified.** Self-Refine returns latest; Reflexion returns last evaluated; CRITIC may return an unverified last correction; OPRO/Optimizer preserve best; GEPA preserves specialist candidates and returns highest mean validation; interactive evolution returns the final active population. Report return-selection policy explicitly.
4. **Mutation policy can itself be the candidate.** Promptbreeder changes mutation instructions and task prompts together. EvoPROMPT's operator sequence is fixed. OPRO leaves proposal strategy implicit in a fixed meta-prompt. GEPA focuses an evidence-conditioned update on one named component. These are different meta-learning depths.
5. **Search feedback and knowledge feedback differ.** GEPA's validation affects parent selection and merge screening but is not shown to the reflection model. Meta-Prompting's gold set gates acceptance but supplies no critique to the optimizer. Both sets influence search and cannot serve as untouched final-test evidence. Local code expects callers to supply correct disjoint splits; it does not prove split integrity.
6. **Human events and sampled evaluator rewards need different accounting.** Human votes can arrive after a candidate retires; interactive evolution stores them in the archive. EPO repeatedly samples arms and estimates means. OPRO deduplicates exact candidates, EvoPROMPT caches by default, and Promptbreeder compares existing scores that may come from different sampled batches. These policies should remain explicit.
7. **EoT, RAG and training are distinct layers.** EoT is strategy-conditioned inference; TAUCHI retrieval is working context; STaR is weight learning. Calling all of them recursive self-improvement hides the actual state transition.

## Suggested extraction order

First, preserve rich evaluation observations and explicit change decisions, then compose the existing candidate generator with **feedback-conditioned revision + strict incumbent retention**. `optimizer` supplies the simplest baseline. Add a bounded reflection context only if attempts repeat mistakes; use CRITIC evidence collection when external verification is available.

Next, add **cross-task experience extraction and retrieval** using ExpeL's separation of experiences, general rules, and successful demonstrations. Preserve TAUCHI's source/generated distinction and quote provenance where document retrieval is relevant. Verify reuse against held-out tasks rather than reporting a growing memory count as improvement.

For diverse code tasks, add **per-instance score vectors and specialist parent selection**, with GEPA-style component targeting and staged evaluation. For expensive noisy scorers, evaluate a bounded batch using EPO's allocation ideas. Add Promptbreeder's evolving operator prompts only after a fixed operator baseline establishes whether operator adaptation improves quality per cost.

Treat **STaR as a separate optional training extension**. Its reusable first piece is verified training-row construction; backend provisioning and model training are outside the current conceptual extraction.

## Evidence limitations

The local implementations deliberately generalize original algorithms through injected models/evaluators and new prompts. Local source is strong evidence for current behavior, not proof that every port reproduces a paper. This audit does not transfer published performance numbers to this workspace or to RSIKit.

TAUCHI has a specific source-provenance gap documented in its README; it combines described system components rather than porting a verified TAUCHI repository. Meta-Prompting's paper presents a theoretical architecture and uses strong claims about deterministic audit signals/convergence; the inspected local implementation cannot establish those guarantees. Its exact partition clustering and per-case regression rules are engineering decisions, not verified novel results. Promptbreeder's co-author implementation is explicitly a later minimal implementation inspired by the paper. The local EoT README records unavailable author code.
