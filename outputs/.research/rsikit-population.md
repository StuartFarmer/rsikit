# Population and operator research for RSIKit

Investigated 2026-09-16. Scope: 16 local implementations (`eoh`, `eoh_s`, `meoh`, `reevo`, `ael`, `llm_ga`, `llm_gp`, `llm_gi`, `llm_gi_2025`, `llm4moea`, `ccmo_llm`, `llm_psro`, `evoprompting`, `alpha_gpt`, `lmca`, `llm_evolution`). Read each `agent.py`, each prompt template, relevant README fidelity notes, and LMCA analysis/grammar and Alpha-GPT retrieval helpers. These findings describe inspected local implementations. Primary pages corroborate method identities and central contributions; detailed paper/code discrepancy statements below are attributed to local fidelity notes unless independently checked. No benchmark runs or performance ranking.

The useful decomposition is **representation + evidence + proposal operators + parent selection + survival + feedback state + update timing**. Named algorithms mostly choose different combinations. Four distinctions must survive extraction: objective vectors versus per-case results; parent selection versus survivor selection; proposal changes versus generator training; and a search population versus an archive versus a deployment mixture.

## Proposed conceptual module boundaries

These are extraction boundaries and callable contracts, not a request for 12 new classes or files. Existing RSIKit equivalents should be reused first.

| Conceptual module | Minimal input → output | Evidence it must preserve | Reuse / first source |
| --- | --- | --- | --- |
| **Artifact and change representation** | `apply(base, proposal) -> artifact`; optional `describe(artifact)`, `targets(artifact)`, `fingerprint(artifact)` | Whole text, thought+text, fragment edits, reversible patches, and real vectors are different representations. A description is not measured evidence. | EoH thought/code; GI fragment/patch operations; LLM4MOEA vectors. |
| **Measured evidence** | `evaluate(artifact, context) -> measurements + validity + diagnostics` | Explicit meaning for scalar objective, objective vector, per-case vector, constraint residuals, pairwise payoff. Preserve instance IDs/order, units/directions and evaluation context/version. | Every agent; strongest schemas from GI, EoH-S, MEOH, CCMO, PSRO. |
| **Parent/context selection** | `select(population, evidence, rng, count) -> ordered parents` | With/without replacement, repeated IDs, ordering, and equality behavior. Distinguish stochastic rank/tournament selection from model selection and behavioral farthest-pair selection. | EoH rank, AEL uniform, LLM-GP tournament/model, EoH-S behavioral diversity. |
| **Proposal operators** | `propose(task, parents, operator_context) -> artifact_or_change` | Operator intent and arity; whether output is final or an intermediate artifact; independent proposal context versus shared Session. A batch needs not be one model call. | EoH five operators, AEL/LMEA sequential variation, EvoPrompting combined crossmut. |
| **Survival/acceptance** | `survive(incumbents, evaluated_offspring, capacity) -> retained` | Scalar elite selection, strict hill climbing, model-chosen replacement, portfolio coverage, dominance/similarity, constrained dominance, and neutral acceptance are alternatives. Do not hide them behind a universal scalar score. | AEL/EoH, GI, LLM-GP, EoH-S, MEOH, CCMO, LMCA. |
| **Archive and eligibility** | `observe(candidate, evidence)` plus `eligible(view)` | Best-so-far archive, Pareto archive, negative-example memory, currently selectable population, and retired parent pool have distinct lifecycles. | ReEvo elite, MEOH Pareto, EvoPrompting retirement, PSRO append-only expansion. |
| **Reflection and memory** | `reflect(comparison_or_failures, prior) -> guidance`; `select_memory(query) -> context` | Measured comparison → hypothesis/guidance; provenance to candidates; operator-specific versus global scope; bounded/compressed versus complete memory. | ReEvo pair/long reflection; LLM-GA negative lists; Alpha-GPT reviews and retrieval. |
| **Schedule and state visibility** | Explicit loop policy deciding `when propose / evaluate / admit / replace / reflect` | Generation snapshot (EoH), operator snapshot then replacement (LLM-GA), live parent pool (MEOH), sequential hill climb (GI), neutral chain (LMCA), outer research round (Alpha-GPT). These change the method even if modules match. | Keep a small explicit recipe per family; do not bury timing in generic callbacks. |
| **Repair and failure policy** | `repair(rejected_artifact, diagnostic, remaining_budget) -> valid_artifact_or_failure` | Proposal parsing, domain invalidity, evaluation failure and infrastructure error are distinct; retry count and fallback order explicit. Feasible constraint violations must not become repair failures. | LMCA and Alpha-GPT; contrast CCMO infeasible data with EoH invalid code. |
| **Generator adaptation** | `update_generator(current_generator, selected_training_records) -> next_generator` | Which samples train, whether base model is frozen, optimizer/soft prompt state, checkpoint identity. Keep separate from passing reflections in context. | EvoPrompting only among these 16 requires training for full method. LLM4MOEA fixed LO is offline behavior distillation, not this hook. |
| **Research direction and external knowledge** | `plan(task, retrieved_knowledge, measured_results, feedback) -> hypothesis + proposal_guidance` | Retrieved IDs must remain valid within chosen scope; directions influence proposals, not silently change evaluator/objective. | Alpha-GPT; useful optional outer loop around code search. |
| **Diagnostics and accounting** | Append attempt/measurement/lineage records; `analyze(records) -> summary` | Model calls, candidates proposed, evaluations actually invoked, cached assessments, matches played, training cost, and accepted transitions are different quantities. Preserve unsuccessful work. | LMCA recurrence; all agents' attempts; LLM-GP cache counter mismatch illustrates need for distinct metrics. |

## Compositions that retain the important differences

- **EoH baseline:** thought/artifact proposal + five fixed operators + rank parents + scalar evaluator + full-generation snapshot + elitist survival.
- **ReEvo-like reflective search:** scalar candidates + unequal-score pair selector + pair reflection + crossover + compressed memory + elite mutation + offspring population, with all-time elite retained separately.
- **EoH-S portfolio search:** per-case cost evaluator + farthest-behavior pair or local parent + complementary survivor selection. Requires case-level results; cannot reconstruct portfolio coverage from scalar averages.
- **MEOH tradeoff search:** objective vector evaluator + dominance-masked code similarity + softmax parents + live parent pool + Pareto archive. Requires similarity as well as objective direction metadata.
- **GI patch search:** stable target locator + replacement proposal + reversible patch application + correctness-gated runtime measurement + strict per-method acceptance.
- **EvoPrompting:** metric-conditioned crossmut + eligible-child archive with retirement + selected training data + real soft-prompt update callback. Keeping the search but dropping the callback is a distinct ablation.
- **PSRO:** matchup evaluator + empirical game + mixture solver + best-response proposer + response selection + growing strategy population. This is a separate search recipe, not an elitist ranking preset.

## Extraction priorities and limits

Start with the ordinary code-search path: proposal/operator library, explicit parent selection and survivor functions, richer measured evidence, and reflection state. Add EoH-S and MEOH as two different recipes to prove the evidence API does not collapse cases and objectives. Add targeted patches when optimizing existing programs rather than generating whole artifacts. Keep numeric-vector optimization, game-theoretic mixtures, soft-prompt training and hierarchical RAG optional; each needs a concrete downstream task or backend.

Avoid copying accidental local behavior into a universal foundation. Duplicate treatment differs: EoH retains equal-fitness distinct candidates; GI can re-evaluate duplicates; LMEA caches exact text; LMCA must retain self-loops; PSRO allows duplicate strategies; EvoPrompting retires already-used parents. Caching is only sound when evaluator context and stochastic measurement policy support it. Stable ties, replacement timing, initialization budgets and final partial batches belong in each recipe's documented semantics.

Most of these methods improve an artifact, heuristic population, or search context while the proposing LLM stays fixed. That is different from changing the optimizer itself or training model parameters. The strongest reusable innovations here are **different ways of constructing proposal context and measured selection**, with EvoPrompting adding an actual generator-learning stage.

Primary-source verification limits: central identities/contributions were checked on author repositories, arXiv records/HTML or publisher proceedings. Pinned Gin URLs returned fetch/cache errors; conference/journal distinctions therefore remain grounded in local implementation and its cited artifact mapping, not a fresh external code audit. No claim that these ports reproduce published numerical results.
