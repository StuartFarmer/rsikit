## Conceptual boundaries worth preserving

1. **History, selectable population, active parent, and returned champion are different state.** DGM selects any admitted functional ancestor; AlphaEvolve selects cell/objective champions but stores more history; Eureka and optimizer dialogue may advance through regressions while returning an earlier champion. A single `keep_best()` abstraction loses behavior.
2. **Selection, generation, and admission are separate decisions.** In-context QD requests a niche but admits by measured behavior. Zero-shot selection resamples only invalid operators. EvoX deploys valid strategy before measuring its utility. These must not be collapsed into one score threshold.
3. **Credit is contextual.** Candidate quality, child productivity (QUBE), local/global normalized progress (AdaEvolve), window improvement (EvoX), and downstream improvement utility (STOP) evaluate different objects. Record parent/operator/strategy IDs and evaluation budget with outcomes.
4. **Adaptation has distinct levels.** Numerical knobs and prose tactics (AdaEvolve), evolved guidance (AlphaEvolve), executable selection policy (EvoX), recursive task-agent source (DGM), and recursive optimizer source (STOP) require different execution capabilities and validation.
5. **Diversity has several meanings.** Exact behavior signatures (QUBE), discretized behavioral coordinates (In-context QD), per-objective cell champions (AlphaEvolve), lexical distance (AdaEvolve), objective-space neighborhoods (SoS), and environment diversity (PINSKY) are not interchangeable metrics.
6. **Interventions should preserve attribution.** Migration/spawn/reset differs from model mutation; migrated improvement should not be credited as newly generated progress. Frozen transfer snapshots prevent within-phase cascading.
7. **Evaluation may itself contain optimization.** Eureka trains a policy; STOP runs an improver; PINSKY tests a policy against an environment; ordinary artifact evaluation may be cheap and direct. Nested calls need explicit counters and budget scopes.
8. **Core execution boundary remains external.** Local loops mostly consume text, providers, and async evaluators. DGM/STOP require caller isolation; EvoX supplies process separation but no security boundary. Do not turn source validation into a claim of sandboxing.

## Suggested extraction order (dependency order, not performance ranking)

Start with artifact snapshots + evaluation evidence + attempt/lineage records; keep archive/history/active/champion distinct. Add independent selection, context, proposal and admission functions. Then implement simple archives and measured behavior descriptors, feedback adapters, staged evaluation and explicit budgets. Add adaptive statistics and interventions after those records exist. Executable policy evolution, recursive execution and environment coevolution are separate later compositions with genuinely different input contracts, not flags on one enormous agent class.
